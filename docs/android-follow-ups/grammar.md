## Logic to mirror and test with the same vectors
- **Option order** (SPEC "Option order"): FNV-1a 64-bit of `<item id>#<seen>` seeds SplitMix64 (`state = seed`); Fisher-Yates from the end with `next() mod (i + 1)` (unsigned). Use unsigned 64-bit arithmetic with wrapping (Kotlin `ULong`; `Long` division and `%` are signed: do not use them). The vectors in SPEC.md are the test, including `("do-does-did-1", 0, 3)` = `[2, 0, 1]`. `answer` and `feedback` stay in file order; `fixedOrder` items are never shuffled.
- **Day**: starts at 04:00 in the device's local time zone; day number = whole days between 2001-01-01 and the local date (device zone) of the instant minus 14,400 seconds of elapsed time: Kotlin `instant.minusSeconds(14400)`, NOT `LocalDateTime.minusHours(4)`; then `atZone(zone).toLocalDate()`. On days with a time change the 04:00 boundary moves one hour. Vectors: local 2001-01-02 03:59 -> 0; 04:00 -> 1; 2001-01-01 02:00 -> -1 (never stored); America/New_York 2025-03-09: 08:59:59Z -> 8832, 09:00:00Z -> 8833; 2025-11-02: 07:59:59Z -> 9070, 08:00:00Z -> 9071; America/Sao_Paulo 2018-11-04 (change at midnight): 06:59:59Z -> 6515, 07:00:00Z -> 6516. A clock before 2001 gives negative days: use comparisons, never ranges that can be empty (`0..today` trapped on iOS).
- **Practiced**: 2 right answers on 2 different review days to 2 different items; the pretest answer (answered as pretest) is excluded, a later answer to the same item after "Skip to the rule" is a normal Try it answer; stored as `rightDays` entries `(day, item)` (at most 2): added when the list is empty, or has one entry and its day and its item both differ from that entry; with 2 entries nothing is added. On reading: entries in file order; an entry that is invalid (item not in the rule, day outside 0..today) or does not fit is skipped and the next tried, until 2 are kept: [(5,a1),(5,a2),(6,a2)] -> [(5,a1),(6,a2)]. Boundary vectors: [(5,A)] no; [(5,A),(5,B)] no; [(5,A),(6,A)] no; [(5,A),(6,B)] yes. "In Review" overrides the state label.
- **Pretest** (S22): offered while `pretestDone` and `pretestSkipped` are both false (so leaving the page without answering or skipping offers it again); skip -> never offered again and the item later answered is a normal Try it answer (vectors a, b, c in SPEC S22). An answered pretest item has `seen` 1.
- **Progress file** `tips.json` (schema 2): the format is each platform's own, its limits and meaning are shared. Read at most 512 KB + 1 byte, then decode (the rules file stays 256 KB); the most the other limits allow is about 374 KB (tested). Not UTF-8 (first non-white-space byte after an optional BOM must be `{`, no 0x00 byte), a raw control character inside a string, nesting over 8 containers (the root object is depth 1, counted on raw bytes outside strings), unparseable JSON, another schema or a non-numeric clock give empty progress, never a crash. Types: a wrong type or null reads as 0 (counts), false (flags) or none (days, optional fields); a rule, item or `rightDays` entry that is not an object is dropped alone. Counts and box: decimals truncate toward zero, then saturate (3.7 -> 3, -0.5 -> 0, 1e30 -> 1000, -1e30 -> 0, 18446744073709551616 -> 1000). Day numbers, `opened` and `schema` are integers only as integer literals (`5.0`, `1e1`, `"schema": 2.0` are NOT: check the raw literal, as iOS `GrammarJSON` does, including escaped keys). Day numbers must be 0...today (`due`: 0...today+31), dropped before any date conversion; `opened` between 2020-01-01 and now, inclusive, whole seconds, no slack (clock set back: the entry loses its time and leaves Recent; a time before 2020 is not written); counts and box saturate; `lastPair` kept only when it is 2 different items of that rule; at most 200 entries (the ones opened longest ago go first; `opened` absent counts as 0; ties: the greater rule id is kept), 12 items each; an answer never leaves `missed` above `seen`. Per item: `box`, `due`, `seen`, `missed`, `tryMiss`, `reviewed`; absent values are omitted when writing, never null. If the rules did not load, progress is not written; the writer returns nothing rather than empty data.
- **grammar-rules.json** is read strictly: a JSON null anywhere is refused (an optional field is absent, never null); `schema` and `answer` must be integer literals; a raw control character is refused; `books` patterns: words separated by exactly one space (no double, leading or trailing space); a word is exactly `*` or 1+ alternatives separated by a single `|`, each 1+ of a-z (no empty alternative, no `*` mixed with letters).
- **Settings**: one optional boolean `grammarInSpanish` (absent or any other type = default: `es` when the translation language is Spanish and the interface is English, else the interface language, `en` for any other). The rule page toggle names the OTHER language ("Show in English" while Spanish is shown) and writes it; it applies to every rule, notes and feedback.
- **Search**: only the first 100 code points of the query are used (`codePoints().limit(100)`, not `take(100)`); lower-case with `lowercase(Locale.ROOT)`, NFD and drop combining marks, split on anything that is not Unicode category L; every query word prefixes a word of title, rule lines, examples or aliases in both languages. Vectors: U+1D400 as the 100th code point is used, as the 101st is cut; "İstanbul" -> "istanbul"; a final "Σ" gives "σ" in Swift but "ς" in Kotlin (do not depend on it).

## Review: two separate sessions (S7 words, S25 rules)
- A session never contains both kinds. Parity test: build a words session and a rules session from the same data and assert each holds only its own kind.
- **Rules session** ("Review rules" / "Repasar reglas", lightbulb): up to 10 items = at most 5 rules x 2 items; at most 1 new rule per session (a rule is new when no item has `reviewed`); same boxes as S7 (1, 3, 7, 14, 30 days); a wrong item goes back to the first box and repeats once at least 3 cards later (inside the 10); a right answer to an item that is flagged by a Try it miss but not due keeps its box and due day and only clears the flag. `reviewed` stays on "Remove from Review" (restored by Undo), so a re-added rule is not new. A newly added item has `due = today + 1`. A rule leaves Review when every item eligible for this learner (`textLang: "es"` items only count with Spanish) has reached box 5.
- **Selection**: on iOS it exists only as test references in `GrammarRulesFileTests` until the screens PR, so Android must port it (and the option shuffle and "leaves Review at box 5") as core code with the same vectors; leaving Review at box 5 is decided by the Review session code, not by `scheduled()`. Port it into core code and test it with the SPEC's vectors, including one that goes through the full candidate filter (the SPEC paragraph "Review selection" is the text; do not restate it differently). Rule vectors use **today = day 20**: R1 (new, 8, pos 3), R2 (new, 9, pos 1), R3 (10, pos 0), R4 (11, pos 2), R5 (12, pos 4), R6 (13, pos 5), R7 (14, pos 6), R8 (due 25: not a candidate) -> R1, R3, R4, R5, R6 (the skipped second new rule does not count toward the 5); with today = 7 nothing is due and no rule is chosen; R3 (10, pos 0) and R2 (10, pos 5) -> R3, R2; a rule with only a flagged candidate (tryMiss 3, due 10, or no due day at box 5) has key 3. Item vectors use **today = day 6**: a (due 5, pos 2), b (due 5, pos 1), c (due 9, pos 3, tryMiss 4) -> [c, b]; with lastPair {c, b} -> [c, a]; with c's tryMiss 6 and c not due -> [b, a]; plus d (due 4, pos 0, `textLang: "es"`): English-only [c, b], with Spanish [c, d]. A candidate's day is min(due, tryMiss when flagged). A visit with 2 items from a rule sets its `lastPair`, a visit with fewer clears it. Session order: r1a, r2a, r3a, r4a, r5a, r1b, r2b, ...
- `textLang: "es"` items are candidates (and counted anywhere) only when the translation or interface language is Spanish; every rule keeps at least 3 items without it; the pretest item never has it.
- **Entry points**: Grammar tab top: one card only when a rule exercise is due ("Review rules", "4 exercises due" / "4 ejercicios para hoy", singular "1 exercise due" / "1 ejercicio para hoy", button "Review now" / "Repasar ahora"); no card when nothing is due or no rule is in Review. Words tab: the words card as it is plus, only when a rule exercise is due, one secondary row "Review rules · 4" / "Repasar reglas · 4" with a chevron. No tab badges. Large text: the card stacks, the row wraps, 48 dp targets (Material 3), and the session and end screens reflow with full-width buttons. TalkBack: the card and the Words-tab row are each one element, "Review rules, 4 exercises due, button" / "Repasar reglas, 4 ejercicios para hoy, botón" (singular and "more than 50" forms too); the session announces "Rule exercise 2 of 10". N is the count of eligible candidates across all rules in Review, uncapped by the session; above 50 show "50+ exercises due" / "Más de 50 ejercicios para hoy" ("· 50+" in the row).
- **End of session**: the headline is always "Done for today." / "Listo por hoy."; below it, when more are due now, "Done for now. N more due today." / "Por ahora, listo. Hoy quedan N más." (singular "1 more", "Hoy queda 1 más.") with "Keep going" / "Seguir", and "N exercises tomorrow." / "Mañana tienes N ejercicios." (singular "1 exercise tomorrow." / "Mañana tienes 1 ejercicio.") only when N >= 1. "N of M": M grows by 1 for each repeat; "today" is fixed when the session starts. The back button names where the session started ("Back to Words" or "Back to Grammar"). Use plural resources for every count.
- **Add to Review**: "“<rule>” added to Review. Starts tomorrow." / "“<regla>” agregada al Repaso. Empieza mañana." with Undo; "tomorrow" is the next review day (04:00 edge, also when added between midnight and 04:00). After adding, the button reads "Remove from Review" / "Quitar del Repaso" (it clears boxes, due days, `tryMiss` and `lastPair`, keeps `reviewed`; Undo restores all of them; a re-added rule starts at box 0 with due = today + 1, also after leaving Review at box 5); "In Review" is only the row state and what the Grammar card counts. Offered once after the first round of 3 practice items (not after the pretest alone).
